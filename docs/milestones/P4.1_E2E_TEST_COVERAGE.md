# P4.1 — E2E Test Coverage Expansion

> **Date:** 2026-08-19 · **Milestone:** P4.1
> **Scope:** E2E smoke tests for untested pages
> **Approach:** Evidence-first, minimal-change, backward-compatible

---

## 1. Objectives

P4.1 focuses on expanding E2E test coverage for pages that were identified as gaps during the P3.x audit. The goal is to ensure all major application pages have at least a smoke test that verifies:

1. Page renders without JavaScript errors
2. Key UI elements are visible
3. Basic interactions work (toggle, modal open/close)
4. Accessibility baseline is maintained

### 1.1 Pages Selected for Testing

Based on the evidence-first approach, the following pages were prioritized:

| Page | Route | Priority | Reason |
|------|-------|----------|--------|
| `SettingsPage` | `/settings` | High | Complex page with theme toggle, Gmail automation, export, delete data, own accounts |
| `PrivacyPage` | `/privacy` | Medium | Privacy sections, export data, delete account with confirmation |
| `NotFoundPage` | `/*` | Low | 404 handling, error boundary |
| `ProfilePage` | `/profile` | Medium | Profile header, financial summary, quick actions, logout |

### 1.2 Rationale

- **SettingsPage**: Most complex untested page — theme switching, Gmail sync toggles, CSV export, destructive delete data modal, own accounts management for transfer neutrality.
- **PrivacyPage**: Critical privacy compliance page — export data, delete account with DELETE confirmation phrase.
- **NotFoundPage**: Basic error handling — ensures 404 doesn't crash the app.
- **ProfilePage**: User-facing page — financial summary, quick navigation, logout flow.

## 4. Test Architecture

### 4.1 Pattern

All new E2E tests follow the established project pattern:

```typescript
import { test, expect } from 'playwright/test';
import { mintSessionCookie, cleanupTestSessions } from './helpers/mintSession';
import { setupAuthContext } from './helpers/authContext';
import { collectPageErrors } from './helpers/errors';

test.describe('Page name (e2e)', () => {
  let session: { cookie: string; userId: string };

  test.beforeAll(async () => {
    session = await mintSessionCookie();
  });

  test.afterAll(async () => {
    await cleanupTestSessions();
  });

  test.beforeEach(async ({ context }) => {
    await setupAuthContext(context, session);
  });

  test('description', async ({ page }) => {
    const pageErrors = collectPageErrors(page);
    await page.goto('/route');
    await page.waitForLoadState('domcontentloaded');
    // assertions...
    pageErrors.expectClean();
  });
});
```

### 4.3 Strict Mode Safety

Several pages have elements that appear in multiple locations (header + sidebar, card + modal). Tests use `.first()` to safely target the intended element:

| Element | Occurrences | Solution |
|---------|-------------|----------|
| "Pengaturan" heading | header h1 + page h2 | `page.locator('h1').filter(...)` |
| "Hapus Akun CashFlow" heading | card h3 + modal h2 | `.nth(1)` |
| "E2E Seed Admin" | h2 + img alt | `.first()` |
| "Gmail Sync" | sidebar + quick action | `.first()` |
| "404" text | may appear multiple | `.first()` |
