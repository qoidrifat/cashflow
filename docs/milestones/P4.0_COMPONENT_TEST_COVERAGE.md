# P4.0 — Component Test Coverage Expansion

> **Date:** 2026-08-19 · **Milestone:** P4.0
> **Scope:** Component test coverage for critical untested UI components
> **Approach:** Evidence-first, minimal-change, backward-compatible

---

## 1. Objectives

P4.0 focuses on expanding component test coverage for critical UI components that were identified as untested during the P3.x audit. The goal is to improve test coverage for fundamental UI building blocks without changing existing behavior.

### 1.1 Components Selected for Testing

Based on the evidence-first approach, the following components were prioritized:

| Component | Priority | Reason |
|-----------|----------|--------|
| `SessionExpiredDialog` | High | Critical auth flow component with countdown timer and auto-logout |
| `Button` | High | Fundamental UI component used throughout the application |
| `Card` | Medium | Common container component with multiple variants |

### 1.2 Rationale

- **SessionExpiredDialog**: Handles session expiry with countdown timer, auto-logout, and accessibility attributes. Critical for security and user experience.
- **Button**: Core UI component with multiple variants (primary, secondary, outline, ghost, danger), sizes, loading states, and accessibility features.
- **Card**: Versatile container component with multiple variants (default, gradient, outlined) and keyboard interaction support.

## 4. Test Architecture

### 4.1 Mocking Patterns

The new tests follow established project patterns:

1. **Zustand Store Mocking**: Uses `vi.hoisted` for mock variables, enabling proper hoisting of mock factories.

2. **Component Isolation**: Each component is tested in isolation with mocked dependencies.

3. **Accessibility-First**: Tests verify ARIA attributes, roles, and keyboard interactions.

4. **Behavior Over Implementation**: Tests focus on user-visible behavior rather than implementation details.
